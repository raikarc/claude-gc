Hackathon architecture proposal

Robo-Bee Perception Architecture

Visitors upload a video of bees working a flower patch. Perceptron Mk1 finds the flowers, follows the real bees and marks every landing. Our planner turns that into the route a robo-bee should fly, and the web app draws that route on top of the original video.

System diagram

One pipeline, two entry points

The same Python pipeline serves the public web app and an offline batch runner over your bee dataset. The web app is a thin shell: it stores uploads, queues jobs and plays back results. The heavy work (ffmpeg, Mk1 calls, path planning) happens in a worker that has no request timeout.

Request lifecycle

What happens when someone uploads a video

  1. The browser asks /api/jobs for an upload token and sends the file straight to Vercel Blob. Vercel functions cap request bodies at 4.5 MB, so videos must never pass through our API.
  2. The API hashes the video. If we have seen it before, it returns the cached result immediately. Otherwise it inserts a jobs row in Supabase and calls the Modal worker's webhook.
  3. The worker pulls the video, normalizes it with ffmpeg and cuts it into overlapping ~20 s chunks so each Mk1 request stays well inside the 32K-token context.
  4. Each chunk gets three Mk1 requests in parallel (flowers, bee tracks, landing clips). Every response is validated against a Pydantic model and cached by chunk hash + prompt version.
  5. The fuser merges chunks into one timeline. The planner produces the robo-bee route. The worker writes results.json to Blob and flips the job to done.
  6. The browser, subscribed to the job row through Supabase Realtime, shows stage-by-stage progress and then loads the overlay viewer.
Perception layer

What we ask Mk1

Mk1 takes MP4 or WebM, answers grounded questions about it, and returns spatial outputs (points, boxes, polygons, tracks and timestamped clips) when you request them through annotation_format. It also accepts a JSON schema in response_format, which is what keeps our outputs machine-readable.

CallInputPrompt (sketch)Output we keep
Flowers3–5 keyframes per chunk“Box every flower. Label each as bud, open or wilted.”box, bloom state, confidence
Bee tracksVideo chunk“Track each bee. Return a point per sampled frame with a consistent bee id.”bee id, [t, x, y] points
LandingsVideo chunk“Return clips where a bee lands on a flower and starts foraging.”start, end, bee id, location
Few-shot landingReference clip + chunkIn-context video learning: “Find events like this reference.”Second opinion for the landing call (stretch)

Calling it from the worker

Mk1 speaks an OpenAI-compatible API, so the stock SDK works. Confirm the base URL and the exact video content-part shape on docs.perceptron.inc before wiring this up.

from openai import OpenAI
client = OpenAI(base_url=PERCEPTRON_BASE_URL,
                api_key=os.environ["PERCEPTRON_API_KEY"])

resp = client.chat.completions.create(
    model="perceptron-mk1",
    messages=[{"role": "user", "content": [
        video_part(chunk_url),          # per docs
        {"type": "text", "text": TRACK_PROMPT},
    ]}],
    response_format={"type": "json_schema",
                     "json_schema": BeeTracks.schema()},
    extra_body={"annotation_format": "point"},
)
tracks = BeeTracks.model_validate_json(
    resp.choices[0].message.content)

From perception to a flight path

How the planner picks where the robo-bee goes

Mk1 tells us what is in the scene. Deciding where to go is our own code, which keeps it deterministic, cheap to rerun and easy to explain in the demo. The planner scores every open flower, then routes through the best ones.

score(flower) = open_confidence × attractiveness × (1 − coverage)
attractiveness = real-bee visits and dwell time, normalized across the patch
coverage = recent visits, decaying with time since the last landing

Two modes, one toggle

Complement (default) sends the robo-bee to flowers bees like but have not reached lately, which is the gap a pollinator robot should fill. Imitate sets coverage to zero and reproduces where real bees went, which is what you want when generating training demonstrations.

Routing

Pick flowers greedily by score per unit distance until an energy budget (a slider in the UI) runs out, which is a quick heuristic for the orienteering problem. Smooth the path with a Catmull-Rom spline and hover at each flower for the median real-bee dwell time.

Design around these

Constraints that shape the design

Mk1 samples video at up to 2 FPS

Bees move fast, so tracks will be sparse. Fix: interpolate between points in the fuser. Stretch: use Mk1 detections as anchors and fill in frames with a classical tracker such as OpenCV CSRT or ByteTrack.

32K-token context

Long videos cannot go in one request. Fix: chunk with overlap, then match bee ids across the overlap by nearest position in the fuser.

Vercel function limits

Body size and execution time rule out processing video on Vercel. Fix: direct-to-Blob uploads and an external worker. Vercel only ever handles small JSON.

The route is 2D, in image space

A single camera gives no depth, so the route is a projection. Say so in the demo. Stretch: monocular depth estimation to lift the route into 3D.

Moving cameras

Handheld footage shifts flower positions between frames. Fix: favor tripod clips from the dataset for the demo. Stretch: stabilize with ffmpeg vidstab during preprocessing.

Live demo latency

A minute of video means dozens of Mk1 calls. Fix: precompute three showcase videos and cache by hash, so the live upload is a bonus rather than the whole demo.

An all-TypeScript alternative is Inngest or Trigger.dev for the job orchestration plus a small container for ffmpeg. It means one language, but you lose the easy parallel fan-out and the shared batch CLI that Modal gives you.

Features and expansions

What to ship, in order

MVP must demo

  • Upload and overlay: real bee tracks in green, flowers boxed, robo-bee route in honey with an animated bee sprite.
  • Visit timeline under the video. Click a landing to jump to it.
  • Stage progress while the job runs.
  • Three precomputed showcase videos on the home page.

Stretch if time allows

  • Complement / imitate toggle and an energy-budget slider that replan instantly in the browser from cached perception.
  • Pollination heatmap showing which flowers were covered and which were missed.
  • Coverage score: real bees alone vs real bees plus robo-bee.
  • Swarm mode: split flowers across N robo-bees with k-means so their routes don't overlap.
  • Ask the video: free-text questions such as “Which flowers did no bee visit?”, answered with Mk1 video Q&A.

Moonshot pitch slide

  • Training data export of (frame, state, action) pairs for imitation learning, built from every video in the dataset.
  • Human-in-the-loop correction: drag a wrong point to fix it, and the fix becomes a training label.
  • 3D simulation in PyBullet or Isaac Sim using monocular depth.
  • Live feed from a drone or field camera, run in short rolling windows.
  • Plant species and bloom stage identification to prioritize crops.
